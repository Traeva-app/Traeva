# Third-party notices: the PDF reader

The PDF reader (`crates/traeva-core/src/pdf*.rs`, #186) adds the crates below
to the app, and with them data files that are compiled into the binary. This
file explains what the PDF reader adds, with the BSD-3-Clause notices its
compiled-in data and the Brotli crates need.

The notice for the whole app is `src-tauri/resources/THIRD-PARTY-NOTICES.txt`,
generated by `scripts/third_party_notices.py` from the crates and npm packages
compiled into the app, with every license text they ship; it includes this
file at the end. It is bundled into `Traeva.app` (`Contents/Resources`).

## Data compiled into the binary

hayro's default features are on (`embed-fonts`, `embed-cmaps`), because
without them text in fonts that a PDF does not embed is lost.

| Data | From | License |
|---|---|---|
| 14 stand-in Type 1 fonts (`Foxit*.pfb`) | PDFium, through `hayro-interpret` 0.8.0 (`assets/`) | BSD-3-Clause, PDFium Authors and Foxit Software: notice below |
| Adobe's predefined CMaps (`cmaps.brotli`) | Adobe's cmap-resources, through `hayro-cmap` 0.1.0 (`assets/`) | BSD-3-Clause, Adobe: notice below |
| CMYK colour profile (`CGATS001Compat-v2-micro.icc`) | Compact-ICC-Profiles, through `hayro-interpret` | CC0-1.0 (no conditions) |
| Lab colour profile (`LAB.icc`) | generated with LCMS2, per `hayro-interpret`'s `assets/README.md` | CC0-1.0: `hayro-interpret` states no license for it, but the same file (same SHA-256) in `hayro-jpeg2000` 0.4.1 is CC0-1.0 by that crate's `assets/README.md` |
| ProPhoto colour profile (`ProPhoto-v2-micro.icc`) | Compact-ICC-Profiles, through `hayro-jpeg2000` 0.4.1 (`assets/`) | CC0-1.0 (no conditions) |

`hayro-jpeg2000`'s CMYK profile is compiled only with its `image` feature,
which is off.
